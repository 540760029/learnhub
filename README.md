# LearnHub · 课程学习与 AI 出题平台

面向高校课程的在线学习平台：**教师**发布课程/知识点/作业/试题并查看学情，
**学生**加入课程、交作业、做模拟题看解析，并可让学生用 AI 按自己的**薄弱知识点**自动出题。

> 当前进度：**P1 本地可运行 Demo（已完成并通过 55 项端到端测试）**
> 技术选型已按「可平滑迁移到 Postgres / 云端」来写，见文末《上线路线》。

## 二、功能清单

### 管理员（平台级）
- **🔑 平台 AI Key**：**上传 / 更新平台默认 API Key**（加密存库，**对全体用户生效**）
  - 可选服务商（DeepSeek / OpenAI / 通义 / 智谱 / Kimi / 自定义 OpenAI 兼容）
  - 自定义模型名与 Base URL
  - **教师/学生每日额度**可随时调整（默认 3 套）
  - **启用 / 停用**平台 AI；留空 Key 不会覆盖已有配置
  - **🧪 测试连通性**：真发一次最小请求验证 Key 是否可用（会显示模型回复）
  - **清除平台 Key**：清除后所有用户回到离线模拟题
- **总览**：用户 / 教师 / 学生 / 管理员数，课程、知识点、试题、题目、作业、
  提交、答题记录、今日 AI 调用次数
- **用户管理**：搜索、改角色（教师↔学生）、设为/取消管理员、停用/启用、删除
- **课程管理**：查看全部课程（含教师、邀请码、各项计数）、进入任意课程、删除课程
- 自己的 AI 出题**不受次数限制**；可进入任意课程代为管理

### 教师
- 创建课程 → 自动生成**邀请码**，学生凭码加入
- **发布知识点**，并选择**可见范围**：全班可见 / 仅教师可见
- **上传资料自动整理知识点**：上传 `.docx / .txt / .md / .csv`，
  AI 切分成知识点 → **预览可逐条编辑、取消勾选** → 统一选可见范围后入库
- 发布 / 编辑 / 删除知识点（含学生提交的私有笔记，教师可见但不可改）
- 发布**作业**（要求、满分、截止时间），查看提交并**打分 + 写评语**
- **手工组卷**：单选 / 多选 / 判断，含答案与解析
- **试题列表与详情**：每套题可点进详情页查看——
  **题目与答案解析**、每题全班正确率、**作答人次/人数/平均正确率/最高正确率**、
  每个学生的得分与错题号，并可跳转看该生答卷
- 可随时切换某套卷的**可见性**（全班可见 / 仅教师可见）
- **学情分析看板**：班级薄弱知识点排行、学生明细、答题趋势
- 学生名单（学号、邮箱、答题次数）

### 学生
- 凭邀请码加入课程
- 查看**全班可见**的知识点、查看作业要求、**在线提交作业**（可反复更新直到被打分）
- 做模拟试题 → **提交后立刻看每道题的解析**，错题自动计入薄弱点统计
- **提交前校验**：作答页顶部有**题号导航**（已作答的变绿，点击即跳题）；
  点「提交」时先弹对话框 —— **没做完不允许提交**，列出哪些做了、哪些没做，
  **点未完成的题号直接跳过去继续做**；全部做完才弹确认框提交
- **交卷后小结**：显示「共几题 / 已作答几题 / 未作答几题 / 答对几题 / 答错几题」，
  并列出**未作答与答错的题号按钮，点一下直接跳到该题**（目标题会高亮闪一下）
- **正确选项自动标绿**（带「✓ 正确答案」角标），选错的标红（带「✗ 你的选择」）
- **答完后可选择**：看解析、**🔄 重新作答**（历史成绩保留在练习记录里）、
  或直接再让 AI 出一套
- **AI 智能出题**：勾选知识点（或点"我的薄弱知识点"排行）→ AI 出题 → 作答 → 看解析
  - 学生生成的题**只有自己能看到**，用于自我强化
- **添加自己的课程笔记**：自己整理的知识点**强制仅本人可见**，可随时改/删；
  老师能看到（便于了解学情），但其他同学看不到
- **我的练习记录**：历史成绩 + 可重新看每一题的解析

## 三、AI 出题额度规则（核心设计）

**平台默认 Key 由管理员在后台「🔑 平台 AI Key」页面上传**，加密存入数据库，
对全体用户生效；额度上限也由管理员随时调整。

| 角色 / 用谁的 Key | 额度 |
|---|---|
| **任何角色用自己的 Key** | **不限次数** |
| **管理员**（用管理员配置的平台默认 Key） | **不限次数** |
| 教师（用平台默认 Key） | 每日 **N** 套（N 由管理员配置，默认 3） |
| 学生（用课程教师 / 平台默认 Key） | 每日 **N** 套（同上） |
| 平台 Key 未配置或被停用 | 降级为**离线模拟题**，流程照样跑通 |

Key 使用优先级：**自己的 Key → 管理员配置的平台 Key（管理员无限）→
课程教师的 Key → 管理员配置的平台 Key（受限）**。

- 生成**失败不扣额度**（额度只在成功落库后才 +1）
- Key 用派生密钥**对称加密后入库**，接口只回显**后 4 位**
- 前端**永远拿不到**完整 Key，`F12` 也看不到；管理员也无法通过接口取回明文
- 环境变量 `LEARNHUB_PLATFORM_API_KEY` 仅作**容器化部署的初始化兜底**，
  数据库里配置了就以数据库为准

## 四、可见性（scope）模型

知识点与试题都带 `scope` 字段，三档：

| scope | 谁能看到 | 谁创建 |
|---|---|---|
| `course` | **全班**（所有学生 + 教师） | 教师 |
| `teacher` | **仅教师**（学生完全不可见） | 教师 |
| `private` | **仅创建者本人**（教师能看到以便答疑） | 学生（强制） |

学生**无法**把自己的知识点或试题设为公开——后端强制改写为 `private`，
即使绕过前端直接调 API 也会被拦。

## 三、项目结构

```
learnhub/
├── app.py            FastAPI 应用：全部 REST 路由 + 权限校验 + AI 出题编排 + 管理员接口
├── db.py             SQLAlchemy 2.0 模型：13 张表（含 settings）+ 增量迁移，可直接迁 Postgres
├── security.py       密码哈希(PBKDF2) / 会话令牌(HMAC 签名) / API Key 加密(Fernet)
├── llm.py            AI 层：6 家 OpenAI 兼容服务商 + 出题 + 资料→知识点提取 + 离线 Mock
├── seed.py           演示数据（3 账号 + 1 课程 + 4 知识点 + 作业 + 4 题试卷）
├── smoke_test.py     端到端冒烟测试（143 项）
├── feature_test.py   答题小结 / 正确项标记 / 解析必填 / 难度规范化测试（69 项）
├── ui_probe.py       无头浏览器端到端验证（提交前校验对话框，需先起服务）
├── upload_test.py    文件上传 / 解析 / 整理 / 入库专项测试
├── requirements.txt
├── .env.example      环境变量模板
└── static/           前端（零构建、零 CDN，纯原生 HTML/CSS/JS）
    ├── index.html
    ├── app.css
    └── app.js
```

### 数据表

`users`（教师+学生同表，`role` 区分）· `courses` · `enrollments`（选课）

## 四、权限模型（多教师多租户）

| 操作 | 课程负责人 | 协助教师 | 选课学生 | 其他人 |
|---|---|---|---|---|
| 看课程内容 | ✅ | ✅ | ✅ | ❌ 403 |
| 发知识点/作业/试题 | ✅ | ✅ | ❌ 403 | ❌ |
| 看学情分析/学生名单 | ✅ | ✅ | ❌ 403 | ❌ |
| 交作业 / 答题 | ❌ | ❌ | ✅ | ❌ |
| 看别人的答题记录 | — | — | ❌ 403 | ❌ |

隔离依据是 `courses.teacher_id`（课程属主）与 `enrollments`（选课关系），
不依赖任何"只有一个老师/一个班"的假设，所以能直接支撑多教师 + 上千学生。

## 五、配置项（`.env.example`）

| 变量 | 说明 |
|---|---|
| `LEARNHUB_SECRET` | 会话签名 + Key 加密主密钥，**生产必须改** |
| `LEARNHUB_DB_URL` | 数据库地址，默认本地 SQLite |
| `LEARNHUB_PLATFORM_API_KEY` | 平台兜底 Key，留空则走离线模拟题 |
| `LEARNHUB_DEFAULT_PROVIDER` | 默认服务商，默认 `deepseek` |
| `LEARNHUB_DAILY_AI_LIMIT` | 非自带 Key 的每日出题套数，默认 3 |
| `LEARNHUB_SEED` | 是否写入演示数据 |

支持的 AI 服务商（学生可在「设置」里自选）：
**DeepSeek**（默认）· OpenAI · 通义千问 · 智谱 GLM · Kimi · 自定义 OpenAI 兼容端点。

## 六、上线路线（后续阶段）

| 阶段 | 内容 | 关键改动 |
|---|---|---|
| ✅ **P1** | 本地 Demo | FastAPI + SQLite |
| **P2** | 数据上云 | 换 `LEARNHUB_DB_URL` 为 Postgres（Supabase 免费档）；模型用了通用类型，基本不用改写 |
| **P3** | 前端部署 | 静态文件推 GitHub Pages；API 部署到 Render/Railway/Fly，或改用 Supabase Edge Function |
| **P4** | 规模与安全 | Supabase RLS 兜底数据隔离、Redis 限流、对象存储放作业附件、操作审计日志 |
| **P5** | 教学增强 | 班级/学期体系、题库组卷、自动批改主观题、知识点掌握度雷达图 |

> ⚠️ **安全提醒**：课程内容与学生数据**绝不能**放进 GitHub Pages 仓库（公开可下载）。
> 前端只放空壳页面，真实数据全部通过登录后的 API 获取 —— 本 Demo 已是这个结构。

## 七、已知取舍（Demo 阶段）

- 会话令牌用标准库 HMAC 自签名（JWT 的极简等价物），上线可无缝换成 PyJWT
- 额度按 UTC 自然日计算，未做"跨时区按用户本地日历日"处理
- 主观题（`short`）目前只做参考答案展示，未接自动批改，需要教师人工评分
- 附件上传未实现（预留了 `submission.attachment_url` 字段），当前用文本提交
- 无 WebSocket 实时通知，学生需刷新才能看到新作业
